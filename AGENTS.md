# AGENTS.md

Guidance for AI coding agents (and humans) working on this repository.

## Project

Meta-repository aggregating the [AnywidgetInstruments](https://github.com/AnywidgetInstruments)
repositories as git submodules, so that a change crossing several of them can be
made and checked in one working tree. It holds no code of its own: only
`README.md`, this file and `.gitmodules`.

Each submodule has its own rules. Before working in one, read its `AGENTS.md`
when it has one; they take precedence over this file for that submodule.

## Submodules

| Path | Content | Stack |
|---|---|---|
| `anywidget-instruments` | the **core**: base view and Python base class, base **trait contract** (JSON Schema) and its generator, themes and styles, liveness; no widget | TypeScript sources, Python package |
| `anywidget-instruments-industrial` | `anywidget-instruments-industrial` (module `anywidget_instruments_industrial`): instrumentation widgets (knobs, gauges, LEDs, charts, alarms, supervisory objects), built on the core | TypeScript front end, Python package |
| `anywidget-instruments-automotive` | `anywidget-instruments-automotive`: automotive instruments (speedometer, tachometer, tell-tales, cluster, …), built on the core | TypeScript front end, Python package |
| `anywidget-instruments-aeronautics` | `anywidget-instruments-aeronautics`: flight instruments (airspeed, attitude, altimeter, …), to be built on the core; design stage (specification only) | Markdown, MkDocs |
| `Anywidget.jl` | Julia host for anywidget front-end modules (AFM): standalone HTML, Jupyter, Pluto, Kaimon Slate | Julia |
| `AnywidgetInstruments.jl` | The anywidget-instruments widgets in Julia, hosted by Anywidget.jl | Julia |
| `afm-host-panel` | Grafana panel plugin hosting AFM modules, with the anywidget-instruments widgets built in | TypeScript, Grafana |
| `anywidgetinstruments.github.io` | the organization site (<https://anywidgetinstruments.github.io/>), MkDocs, brand images from `dotgithub` | Markdown, MkDocs |
| `dotgithub` | the organization's `.github` repository: profile page (`profile/README.md`) and visual identity (`brand/`) | Markdown, SVG, Python generator |

## How the repositories depend on each other

```
anywidget-instruments   (core: base view and class, base contract and generator, themes, liveness)
 ├── anywidget-instruments-industrial   pins the core at a commit (package.json); widgets + bundle
 │     ├── AnywidgetInstruments.jl      vendors the bundle, contract and schemas (assets/)
 │     │     └── Anywidget.jl           hosts the front end in Julia
 │     └── afm-host-panel               vendors the bundle (src/widgets/anywidget-instruments-industrial/)
 ├── anywidget-instruments-automotive   pins the core at a commit (package.json); widgets + bundle
 │     └── afm-host-panel               vendors the bundle (src/widgets/anywidget-instruments-automotive/)
 └── anywidget-instruments-aeronautics  design stage: specification only, no code yet
```

- The traits common to every widget live in
  `anywidget-instruments/src/anywidget_instruments/schema/instrument.schema.json`;
  the traits of a widget, in its library's `schema/` directory, which extends
  the base schema by its `$id`. Change a trait there first, then propagate it
  to the libraries and hosts; never patch a vendored copy.
- A widget library depends on the core only, never on another library. After a
  change of the core, push it, move the pin of each library (`package.json`
  and its lockfile) to the new commit and run their checks.
- The front end is the implementation. Anything a widget displays is computed
  in the TypeScript front end; hosts (Python, Julia, Grafana) only set traits.
- Anything general enough to serve every instrument family belongs in the
  core, anywidget-instruments, not in a widget library or a host.
- Vendored files are regenerated by scripts, never edited by hand:
  - `AnywidgetInstruments.jl`: `just sync-assets [wheel]` (`scripts/sync-assets.sh`,
    from a built wheel; `assets/SOURCE.toml` records the origin).
  - `afm-host-panel`: `node scripts/vendor-instruments.mjs` and
    `node scripts/vendor-automotive.mjs` (defaults: `../anywidget-instruments-industrial`
    and `../anywidget-instruments-automotive`; build each checkout first with
    `npm install && npm run build`).

## Commands

```bash
git submodule update --init --recursive     # first checkout
git submodule update --remote --merge       # move every submodule to its latest remote commit
git submodule status                        # commit recorded for each submodule
```

Checks are run inside each submodule, with its own tooling:

| Submodule | Checks |
|---|---|
| `anywidget-instruments` | `npm run typecheck`, `npm run lint`, `npm test`, `pytest`, `ruff check . && ruff format --check . && mypy src`, `mkdocs build --strict` |
| `anywidget-instruments-industrial` | `npm run build`, `npm run typecheck`, `npm test`, `npm run lint`, `pytest`, `ruff check . && mypy src`, `npx playwright test` (see its `AGENTS.md`) |
| `anywidget-instruments-automotive` | `npm run build`, `npm run lint`, `npm run typecheck`, `npm test`, `pytest`, `ruff check . && mypy src`, `mkdocs build --strict`, `npx playwright test` (see its `AGENTS.md`) |
| `anywidget-instruments-aeronautics` | `mkdocs build --strict` (documentation and specification only for now) |
| `anywidgetinstruments.github.io` | `mkdocs build --strict`, with `docs/brand/` copied from `dotgithub/brand` (see its README) |
| `Anywidget.jl` | `just check` (format, tests, Slate tests, docs) |
| `AnywidgetInstruments.jl` | `just check` (format, tests, Slate tests, examples, docs) |
| `afm-host-panel` | `just check` (typecheck, lint, test); `just e2e` against a Grafana server |
| `dotgithub` | `python3 brand/make.py` regenerates the logos, banners and PNG exports; never edit them by hand |

After a change of the core, move the pin of both libraries to it. After a
change of the contract or of the front end of a library, rebuild it, re-vendor
it into the hosts and
run their checks too.

## Git

- Commit inside the submodule first, push it, then commit the new submodule
  pointer here. Never record a submodule commit that is not pushed.
- A pointer update here says which submodules moved and why; the details stay
  in the submodules' own history.
- Submodules are checked out on a detached HEAD: switch to a branch
  (`git -C <path> switch main`) before committing in one.
- Author and committer: the repository owner's identity (never an AI identity).
- No `Co-Authored-By` trailer for AI, no model or tool names in commit
  messages, code, comments or documentation.
- When AI assisted the change, end the commit message with `Assisted-by: AI`.
- Commit messages: imperative subject ≤ 72 characters, blank line, body
  explaining what and why.
- Do not rewrite published history unless the owner asks for it.

## Conventions

- Repository content is in English.
- Do not name, cite or compare with third-party products or projects whose
  ideas inspired a feature; describe the feature itself.
